# Next.js development refresh patch

`next@16.4.2.patch` fixes stale interception rewrites accumulating across dev-server
file updates. Without it, editing a file while a hero modal is open can display a
404 and leave subsequent client navigations broken until a full browser reload.

The patch tracks only the rewrites generated by the current watcher, removes them
before installing the next set, and preserves user-defined rewrites. Both CommonJS
and ESM builds are patched. Production build and runtime code are unchanged.

Upstream report: https://github.com/vercel/next.js/issues/91265

Use `bun install` (or `bun install --frozen-lockfile` in CI) to apply the patch via
`patchedDependencies`. npm does not apply Bun patches. Restart `bun dev` after
installing the patch so the server loads the corrected module.

When upgrading Next.js, check whether the upstream fix is included before removing
or updating this version-specific patch.

Regression check:

1. Run `bun dev`, visit `/heroes`, and open Kasel in a modal.
2. Open Gear and edit visible text in `gear-enhancement.tsx` several times.
3. Verify each update appears while the modal stays open without a 404.
4. Search for Frey; verify the new hero opens in a modal.
5. Restore the temporary text edits. A full browser reload should still open the
   normal full detail page.
